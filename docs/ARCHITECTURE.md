# Architecture

Review Insights is a **modular monolith**: one FastAPI process, one relational database, and one
React single-page app. There are no microservices, message brokers, Redis, or paid APIs.

```
booking.com/
├── backend/           FastAPI app, SQLAlchemy models, Alembic migrations, pytest suite
│   ├── app/
│   │   ├── api/         HTTP layer: routers, request/response schemas, error envelope
│   │   ├── services/    Domain logic: normalization, import, collection, classification, analytics
│   │   ├── models.py    Persistence layer (SQLAlchemy ORM)
│   │   ├── seed.py      Stable property seed
│   │   └── cli.py       Command-line entry points (migrate, seed, import, reclassify)
│   ├── alembic/       Migrations (reproducible from an empty database)
│   └── tests/         Unit + API tests; fixtures live in tests/fixtures
├── frontend/          React + Vite + TypeScript + Tailwind + Recharts, Vitest/RTL tests
├── data/              Synthetic sample dataset + generator; local SQLite DB (git-ignored)
├── docs/              Architecture, collection policy, API reference, screenshots
└── scripts/           PowerShell / shell helpers for run, test, lint
```

## Layers

| Layer        | Responsibility                                                                    |
| ------------ | --------------------------------------------------------------------------------- |
| Collection   | Get raw reviews in. `CollectorAdapter` interface; importer (CSV/JSON) is the supported adapter. |
| Processing   | Normalize text/dates/ratings, compute content hash, classify topics, score sentiment. |
| Persistence  | SQLAlchemy models, DB-level constraints and dedup, Alembic migrations.             |
| Analytics    | SQL aggregations for weekly KPIs, property comparison, trends, topic insights.      |
| API          | FastAPI routers, Pydantic schemas, consistent error envelope, OpenAPI at `/docs`.   |
| UI           | React dashboard consuming the API through a typed client.                          |

Dependencies point inward: API → services → models. Services never import from the API layer, so
they can be called from the CLI and tests directly.

## Key decisions

- **SQLite by default, Postgres-compatible.** The project must boot from a clean checkout with no
  external services. All SQL is generated by SQLAlchemy; the import path uses dialect-specific
  `INSERT ... ON CONFLICT DO NOTHING` (both SQLite and Postgres support it). Set `DATABASE_URL` to
  switch databases.
- **Dedup in the database, not just in code.** Partial unique index on
  `(property_id, source_review_id) WHERE source_review_id IS NOT NULL` plus a unique index on
  `(property_id, content_hash)`. Re-running an import is therefore idempotent and safe under
  concurrency.
- **Aggregations in SQL.** Analytics never loads the full review table into Python.
- **Rule-based NLP.** Topics use documented keyword/regex rules; sentiment uses VADER (local, no
  network). Both are approximations and are labelled as such in the UI. See
  [CLASSIFICATION.md](CLASSIFICATION.md).
- **Source of every record is explicit.** `Review.source` is one of `live`, `import`, `synthetic`;
  the API exposes a `data_source` indicator and the UI shows a badge whenever synthetic data is on
  screen.
- **No reviewer PII.** Reviewer names, countries, and avatars are not stored.

## Assumptions

- **Business timezone:** `Australia/Sydney` (configurable via `BUSINESS_TIMEZONE`). A week starts
  Monday 00:00 local time; DST transitions are handled by `zoneinfo`. Timestamps are stored in UTC.
- **"This week"** is Monday 00:00 local → now. **"Previous week"** is the same elapsed span one week
  earlier (e.g. Mon 00:00 → Wed 14:00 compared with the prior Mon 00:00 → Wed 14:00), so partial
  weeks are compared fairly.
- **Rating scale:** Booking.com scores are 1–10. Values are stored on that scale. Imports may
  declare a different scale (e.g. 1–5) and are normalized linearly to 1–10.
- **Missing values are NULL, never 0.** Missing ratings are excluded from averages; missing
  `published_at` dates are excluded from time-based analytics and the exclusion count is reported.
- **Properties** are fixed and seeded with stable IDs (see `backend/app/seed.py`).
- **Data provenance:** Booking.com's Terms prohibit automated access (see
  [COLLECTION.md](COLLECTION.md)), so live collection is disabled. Data enters via manual export +
  import. The bundled sample dataset is synthetic and labelled as such on every record.
